# S7.6 — Model Benchmark & Astra Validation Specification

## 1. Objective
Determine empirically which candidate AI models are best suited for Universal Adaptive Learning Platform (EDUIA) workloads.

Sprint S7.6 is strictly an **EVALUATION sprint**. It preserves the validated core Learning Engine (S1–S6), Assessment & Measurement Engine (S7), and AI Model Orchestrator (S7.5).
In accordance with the core principle:
> *"Choose models based on EDUIA workload evidence, not model reputation."*

No models are assumed superior a priori (Astra vs Claude vs GPT vs DeepSeek). The evaluation measures empirical Quality, Schema Validity, Latency, Cost, and Failure Rates across representative EDUIA pedagogical tasks. Production routing configurations remain protected from silent automated mutation.

## 4. Benchmark Tasks (EDUIA Workloads)
The benchmark evaluates 8 pedagogical tasks representative of EDUIA:

1. **TASK 1 — TUTOR (`tutor`)**:
   - Pedagogical teaching of Python variables & data types to a beginner.
   - Requirements: beginner tone, 1 runnable code example, addresses physical box vs object reference misconception, 1 check-for-understanding question.
   - Evaluator: Deterministic rubric checking assignment syntax, reference misconception address, question syntax, and pedagogical clarity.

2. **TASK 2 — FEYNMAN (`feynman`)**:
   - Evaluation of a learner explanation containing a realistic object aliasing/storage box misconception.
   - Evaluator: `FeynmanEvaluationSchema` with deterministic `calculateFeynmanScore` rubric weighting (§S6).

3. **TASK 3 — DIAGNOSTIC (`diagnostic`)**:
   - Diagnosis of a learner type coercion TypeError (`x = '5' + 3`).
   - Evaluator: `DiagnosticBenchmarkOutputSchema` checking identification of strong typing/coercion, confidence rating, and next step.

4. **TASK 4 — PLAN (`plan`)**:
   - Formulation of a prerequisite-aware learning plan from weaknesses to data analysis objective.
   - Evaluator: `PlanBenchmarkOutputSchema` verifying milestone sequence integrity and prerequisite respect.

5. **TASK 5 — COMPETENCY (`competency`)**:
   - Formulation of a structured competency for Python function parameters.
   - Evaluator: `CompetencyBenchmarkOutputSchema` verifying measurable outcomes and prerequisites.

6. **TASK 6 — ASSESSMENT (`assessment`)**:
   - Generation of an independent multiple-choice psychometric question with options and rationale.
   - Evaluator: `GeneratedAssessmentItemSchema` checking question clarity, options containing correct answer, and explanation.

7. **TASK 7 — MATERIAL (`material`)**:
   - Generation of a concise instructional bite for Python type casting.
   - Evaluator: `MaterialBenchmarkOutputSchema` checking runnable code snippet, common mistake, and core takeaway.

8. **TASK 8 — CLASSIFIER (`classifier`)**:
   - Intent classification for learner query into `SETUP_ENVIRONMENT`.
   - Evaluator: Exact ground-truth accuracy match against `SETUP_ENVIRONMENT`.

## 5. Failure Classification
Every benchmark run categorizes outcomes into distinct failure types:

- **`OPERATIONAL_FAILURE`**:
  - Network timeout, 404 endpoint not found, 429 rate limit exceeded, 5xx server errors, connection resets.
- **`SCHEMA_FAILURE`**:
  - Malformed JSON, unparseable output, or Zod schema validation errors.
- **`CONTENT_FAILURE`**:
  - Schema valid, but semantic answer is incorrect, hallucinated, or fails pedagogical thresholds (e.g. wrong classification category, score < 50).
- **`NONE`**:
  - Full operational, schema, and content success.

## 7. Analysis by Dimension

### A. Quality
- `openai/gpt-4o-mini`: 100% on Classifier, Diagnostic, Tutor, Assessment. 70% on Feynman rubric. Consistently produced high-quality structured outputs.
- `deepseek/deepseek-chat`: 100% quality when responses succeeded, but degraded overall due to operational retry timeouts and upstream 429 errors.

### B. Latency
- `openai/gpt-4o-mini`: Average latency **3,068ms** (fastest structured response: 1,764ms).
- `deepseek/deepseek-chat`: Average latency **11,491ms** (3.7x slower than GPT-4o-mini).

### C. Cost
- Both models are exceptionally cost-effective:
  - Total cost for 5 live EDUIA tasks on GPT-4o-mini: **$0.000657**.
  - Total cost for all 10 live runs combined: **$0.000878**.
- DeepSeek is slightly cheaper per token ($0.14/M input vs $0.15/M), but the savings are negligible compared to latency and reliability tradeoffs.

### D. Reliability
- `openai/gpt-4o-mini`: **100% success rate (5/5)**, 0 operational failures, 0 schema failures.
- `deepseek/deepseek-chat`: **60% success rate (3/5)**, suffered upstream 429 rate-limiting on OpenRouter's shared pool.
