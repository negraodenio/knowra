## 1. Objective

S8.2 transforms Knowra from a functional technical engine into an accessible, credible, and publicly discoverable product. The objective is to provide an acquisition layer where any new visitor immediately grasps:
1. **What is Knowra?** An adaptive learning platform that understands what you know.
2. **Why is it different?** It maintains an empirical learner state rather than linear courses or stateless chatbot sessions.
3. **How does it work?** Through a continuous 7-stage adaptive loop (Goal $\rightarrow$ Diagnostic $\rightarrow$ Map $\rightarrow$ Next Best Action $\rightarrow$ Evidence $\rightarrow$ Mastery $\rightarrow$ Spaced Review).
4. **What can I learn?** 3 curated domains with verifiable competency graphs (Python Junior, Mathematics, Excel Pro).
5. **What should I do next?** Click **Start Learning** to establish a personal learning goal.

## 7. CTA Flow & Routing Architecture (§3, §15, §16, §31)

### Routing Architecture:
- Root route `/` dynamically evaluates learner authentication status:
  - **Unauthenticated Visitor ($!userId$):** Renders public `<LandingPage />`.
  - **Authenticated Learner ($userId$) without active goal:** Renders Goal Onboarding (`"Tell Knowra what you want to learn."`).
  - **Authenticated Learner ($userId$) with active goal:** Renders full active `<LearnerDashboard />`.
  - **Sign Out:** Clicking "Sign Out" in `<LearnerNav />` clears user identity, resets state, and returns learner to the public Landing Page.

### Six Routing Lifecycle Cases Verified (§31):
- **Case A: Anonymous Visitor:** Visiting `/` loads Landing Page with 0 errors or leaks.
- **Case B: Visitor clicks "Start Learning":** Opens `<AuthModal />` or navigates to `/auth`.
- **Case C: New Authenticated Learner:** Authenticates with chosen ID; enters Goal Onboarding.
- **Case D & E: Existing Authenticated Learner:** Automatically loads active goal dashboard, Next Best Action, and learning map.
- **Case F: Learner Signs Out:** Clears `localStorage` keys; renders public Landing Page immediately.

## 18. Known Limitations

1. **Email / Magic Link Supabase UI:** While Supabase server auth is integrated in `lib/auth/get-user.ts`, the frontend auth dialog currently supports learner handle creation and demo profiles for universal zero-config beta onboarding without requiring external SMTP setup.
2. **Offline Mode:** The landing page and dashboard require active network connectivity for LLM planning and database persistence.
