## 3. Product Journey & Information Flow

The canonical learner journey is verified end-to-end:

$$\text{GOAL} \longrightarrow \text{DIAGNOSTIC} \longrightarrow \text{STARTING POINT} \longrightarrow \text{LEARNING MAP} \longrightarrow \text{NEXT BEST ACTION} \longrightarrow \text{ACTIVITY} \longrightarrow \text{EVIDENCE} \longrightarrow \text{MASTERY SHIFT} \longrightarrow \text{NBA REFRESH} \longrightarrow \text{ASSESSMENT} \longrightarrow \text{LEARNING GAIN}$$

### Screen-to-Service Mapping:
1. **Entry & Dashboard (`app/page.tsx`):**
   - *Data Sources:* `/api/goals`, `/api/learning/recommendation`, `/api/learning/state`, `/api/learning/gaps`, `/api/learning/plan`.
   - *Services:* `learningStateService`, `recommendationService`, `gapService`.
   - *Learner Action:* Express goal naturally $\rightarrow$ receive Next Best Action with explicit "Why?" rationale.
2. **Diagnostic Stepper (`app/diagnostic/page.tsx`):**
   - *Data Sources:* `/api/diagnostic/start`, `/api/diagnostic/[id]/answer`, `/api/diagnostic/[id]/complete`.
   - *Services:* `diagnosticService`, `learningStateService`.
   - *Learner Action:* Answer calibrating questions $\rightarrow$ establish permanent, immutable baseline score.
3. **Adaptive Map (`app/map/page.tsx`):**
   - *Data Sources:* `/api/learning/state`, `/api/learning/gaps`, `/api/learning/recommendation`.
   - *Services:* `competencyMapService`, `prerequisiteGraph`.
   - *Learner Action:* Inspect personalized competency tree, current focus node, and prerequisite blockers.
4. **Activity Shell (`app/activity/page.tsx`):**
   - *Data Sources:* `/api/learning/activity`, `/api/learning/activity/submit`.
   - *Services:* `curriculumActivities`, `masteryService`, `recommendationService`.
   - *Learner Action:* Solve challenge / explain concept $\rightarrow$ emit verified evidence $\rightarrow$ update mastery server-side.
5. **Progress & Gain (`app/progress/page.tsx`):**
   - *Data Sources:* `/api/learning/gain/[goalId]`, `/api/learning/assessment/start`, `submit`.
   - *Services:* `assessmentService`.
   - *Learner Action:* Complete independent final assessment $\rightarrow$ inspect pre/post score differential and normalized gain ($g$).
6. **Audit History (`app/history/page.tsx`):**
   - *Data Sources:* `/api/learning/history`.
   - *Services:* `productEventService`.
   - *Learner Action:* Review verified chronological ledger of learning events.

## 7. UX Findings & Hardening Corrections

During the comprehensive audit, several integration and presentation defects were identified and resolved:

1. **Gap Status Filter Mismatch (`app/map/page.tsx`):**
   - *Defect:* The learning map checked `g.status === "ACTIVE"`. In the canonical `LearningGap` schema, active gaps have `status: "OPEN"`. This prevented open gaps from displaying on the map.
   - *Correction:* Updated filter to `g.status === "OPEN"`. Verified active gap alerts now appear correctly on competency cards.
2. **Technical Jargon in Learner Copy:**
   - *Defect:* Terms such as *"DAG"*, *"Baseline Preserved (§44)"*, *"FSRS/SM-2"*, and raw database IDs (`py-variables-types`) were exposed to learners.
   - *Correction:*
     - Changed *"Baseline Preserved (§44)"* to *"Starting Point Established"*.
     - Replaced *"Every node represents a competency in the prerequisite DAG"* with *"Every card represents a key topic in your personalized learning journey"*.
     - Simplified *"Spaced Repetition Review (FSRS/SM-2)"* to *"Spaced Review: Retrieve from memory"*.
     - Formatted raw competency IDs into clean topic titles across question steppers.
3. **Spaced Review Rating Usability:**
   - *Defect:* Plain buttons (`AGAIN`, `HARD`, `GOOD`, `EASY`) lacked memory retrieval context for non-technical learners.
   - *Correction:* Added explicit retrieval cues:
     - `Again` (Forgot)
     - `Hard` (Struggled)
     - `Good` (Remembered)
     - `Easy` (Effortless)
4. **Learning Gain Visualization:**
   - *Defect:* Displaying negative scores in uniform green without pedagogical explanation caused learner confusion.
   - *Correction:* Amber/warm styling for negative gain with transparent pedagogical commentary: *"Score reflects unpracticed competencies or assessment challenge. Targeted review is recommended."*

## 8. Pedagogical Findings

- **Separation of Completion vs. Mastery:** The UI strictly avoids equating activity completion with mastery. Completing an exercise records an evidence point and shifts mastery according to the engine formula, without falsely displaying "Mastered" until the 85% threshold is crossed.
- **Distinct Pedagogical Shells:**
  - *LEARN:* Contextual instruction and key concepts.
  - *PRACTICE:* Immediate problem solving producing verifiable evidence.
  - *FEYNMAN:* Open-ended natural language explanations evaluated on causal reasoning, simplicity, and correctness.
  - *REVIEW:* Spaced retrieval practice reinforcing memory decay intervals.

## 9. Learning Gain Investigation (§18, §37)

### Observed Empirical Data:
- **Baseline Score:** 57.14%
- **Final Assessment Score:** 40.00%
- **Learning Gain:** -17.14 points
- **Relative Gain ($g$):** -40.0%

### Root Cause Analysis:
1. **Category G (Simulation Fixture Bias):**
   - In the automated script, the diagnostic answered alternating questions with `item.correctAnswer` (achieving 4/7 = 57.14%).
   - In the final assessment simulation, the script submitted `item.options[0]` for all questions (an arbitrary guess), achieving 2/5 = 40.0%.
2. **Category D (Insufficient Intervention Breadth):**
   - Between the baseline diagnostic and final assessment, only a single practice exercise on one competency (`py-conditionals`) was executed.
   - The independent final assessment tested all 5 core curriculum competencies, the majority of which remained unpracticed by the learner.
3. **Assessment Independence:**
   - Zero item reuse between baseline diagnostic and final assessment. The final assessment represents an honest, non-overlapping measurement.
4. **Conclusion:**
   - The negative gain is a **legitimate, mathematically sound outcome** of an unpracticed domain coupled with random answering in the simulation.
   - In accordance with Section 37, **the scoring formula was not modified or manipulated to force a false positive**. Knowra remains scientifically honest.
